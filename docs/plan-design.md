# NAN Plan System · 设计文档 v1

## 0. 价值基线

1. **优化目标是逼近影子状态，不是完成任务**。每个条目的影子状态是它要推向的理想世界状态；根影子由用户执笔，至高无上。
2. **规划是 LLM 认知过程**：草案 → 推演 → 筛除，全部在模型内完成。系统只约束产物（动作与条目），不约束思考。
3. **影子不可降级**：发现理想状态按当前手段不可达，第一反应是重规划手段（升能力、换路径、开子栈），不是降低影子。影子的唯一写通道是用户。
4. **计划是严格的序**：条目即先后，条目间无并行；并行只是单条目执行内部的战术（子代理），不属于计划结构。
5. **模块无控制流权力**：planner 的输出通道只有 query 渲染与 DataSpace；它不能唤醒、打断、派发任何东西。响应性由主代理的睡眠纪律保证。
6. **分解粒度由"值不值得有自己的影子"决定**，不由"想并行"决定。计划是里程碑，不是工单。

## 1. 结构：有序树 + 焦点栈

- 存储上是树（森林），执行上是深度优先的焦点栈：任一时刻焦点 = 沿"第一个开放子条目"下探到的最深条目。
- 条目两阶段：
  - **规划期**（planner）：焦点到达 → 分解出有序子条目（各带影子）；缺信息 → 开子栈（挂本条目名下作第一个子条目），本层规划挂起；
  - **执行期**（主代理）：按子条目序推进；单条目过大 → 主代理自行拆工并行。
- JIT 原则：**只规划焦点一层**，兄弟保持"标题+影子"。后面条目的规划自动吸纳前面条目的执行结果；重规划因此天然便宜——未执行条目只是标题+影子。

### 条目状态（全部由结构推导，不设状态字段）

| 状态 | 条件 | 谁的动作 |
|---|---|---|
| 待规划 | 开放、无子条目、非 leaf | planner expand |
| 可执行 | `leaf = true`（expand 空 children 即判定） | 主代理执行 |
| 推进中 | 开放、有开放子条目 | 焦点下探 |
| 待裁决 | 开放、子条目全部闭合 | planner 对照影子裁决 |
| 已闭合 | `closed = verdict` | — |

子条目全闭合的条目有两种语义，由 planner 语义判断：子栈闭合 → 继续完成该层规划（expand）；子树工作完成 → 对照影子裁决（close / note）。

## 2. 数据模型与存储

```
workspace/plan/
├── PLAN.md          # 权威存储：人可读可编辑，parse on demand，热重载
└── decisions.jsonl  # planner 动作与 deliberation 追加日志（审计 + 续规划记忆）
```

条目字段：`id(g-%06d) / parent / order / title / shadow / leaf / missing / closed / closed_at / evidence / gap_report[] / notes[]`。

- 用户直接改 PLAN.md = **amend 级合法外部输入**（影子的第二写通道），下回合生效；
- 坏文件三不：不截断、不覆写、不 raise（Facade 会把 query 异常吞成 None 致盲 agent）——降级到 last-good 投影 + `[Plan|degraded]`；
- `evidence` 引用执行回流编号（`r-%06d`，plan 模块自有序号）；`gap_report` 仅根闭合时必需，`- gap:` 行存储。

## 3. planner think-cycle

### 输入（每次 think）

定案的树（planner 视图，全条目含影子与状态）+ 焦点标注 + 最近推演摘录（decisions 尾部）+ 本轮用户输入 + 执行回流（records 渲染，截断）。

### 输出（一次 think）

```json
{"deliberation": "草案/推演/筛除的自由文本（留档）",
 "actions": [ ...有序动作，级联执行... ]}
```

**一次 think 输出一组有序动作**，级联推进：根确定 → expand 一级 → 焦点进入一级条目规划期 → 继续推演 → …… 直到碰到"需要世界变化才能继续"的点（开完子栈 / 到达可执行叶子）才停。

### 动作集（六 op + 隐式 wait）

| op | 语义 | 守卫 |
|---|---|---|
| `plant_root` | 建根（title+shadow） | 本批必须含用户输入 |
| `expand` | 分解焦点：产出有序子条目（各带影子）；**children 为空 = 判定可直接执行（leaf）**；子栈闭合后续规划 = 追加式 expand | target 必须是当前焦点；纯新增，不动已存在条目；leaf 条目不重规划 |
| `open_substack` | 规划缺信息 → 挂焦点名下（可执行子条目）+ missing | target 必须是焦点；missing 必填 |
| `close` | 闭合焦点，弹栈：父为挂起规划 → 续规划；父为执行序 → 焦点移下一兄弟 | target 必须是焦点（结构上保证无开放子条目）；evidence 必填；**根闭合必须附 gap_report** |
| `note` | 条目注记（渲染"注:"） | target 开放 |
| `amend` | 改影子（阶段 3） | 必须引用本批用户原话（user_quote） |
| `replan` | 单层 surgery（阶段 3） | 只动该层未闭合的待办兄弟 + 焦点后插入；**焦点路径不可触**；payload 无 shadow 字段，幸存条目影子结构上不可改 |
| （空数组） | wait | — |

评估不是动作：对照影子判断现实是每次 think 的认知底噪，结论体现为 close/replan/note/wait。闭合必须引用具体观测，不许自我宣布胜利。

### settle 循环（定案的定义）

```
重复 think（上限 planner_think_cap，默认 4）：
  取批（待定用户输入 + records）；批空 → 停
  think → 校验（模拟树上全量预检，防部分应用）→ 应用 → 落盘 + decisions
  停止条件：动作数组为空 ／ 焦点为可执行叶子 ／ 达到上限
```

**每次定案要么给 agent 一个明确可执行的焦点，要么明确说在等什么。**

## 4. 同步模型

- **query 阻塞即同步**：本模块是"query 不许干活"铁律的唯一豁免者——计划是指令本身，等待规划的延迟就是规划本身。阻塞精确落在主代理第一步；其他模块 query 并发纯读，互不干扰。
- 输入双馈：用户消息在 query 时直喂 planner（`ModuleTurn.turn.user_input` 在场，无需接线）；执行结果经 `on_turn(record)` 入队。settle 即时 flush，无批处理延迟。
- 子代理回合直接早退：不付 planner 税，也不看计划（简报自包含原则）。
- **planner 失败不冻死 agent**：重试一次仍败 → 状态 `degraded`，渲染上次定案树，等下一回合自愈。
- depth>0 的子代理任务绝不能进 planner 输入（防简报被当目标吃掉）。

## 5. 不可降级的结构保障

- 根影子只存在于 `plant_root` / `amend` 的 payload；`replan`/`expand` 结构上摸不到；
- `replan` 无 shadow 字段，幸存条目影子不可触；换影子只能删旧建新，且推演必须对照父影子论证——每层影子的锚是父层，逐层锚在用户手写的根影子上；
- `amend` 必须携带用户原话；
- replan/amend 全程留档（decisions.jsonl），影子洗白至少可审计；
- 根闭合必须产出差距报告（对照根影子逐条列未满足项），agent 不许自我宣布胜利。闭合后计划段渲染为 `[Plan|closed]` + 差距报告，静置等用户；不加"待确认"状态。

## 6. 渲染格式（agent feed，depth==0 专用）

```
[Plan|settled 22:14]                      # manual / settled <HH:MM> / degraded / closed
根 g-000001「title」影子: <根影子，每回合必在——防退化的锚>
  · g-000002 中间路径节点
    注: <该条目最新注记>
    ✓ g-000004 已闭合子条目 → verdict
    ▶ g-000007 焦点 影子: <焦点影子>
      缺: <missing，子栈在场时>
  待办: g-000005 标题 · g-000006 标题      # 开放且不在焦点路径上的全部条目
```

中间层影子不渲染（预算），强调权在注记。根闭合 → `[Plan|closed]` + `差距:` 行。

## 7. 失败与边界

| 场景 | 处理 |
|---|---|
| PLAN.md 损坏 | 降级 last-good + `[Plan|degraded]`，写路径自锁，等人工修复 |
| planner LLM 超时/坏输出 | 同批重试一次（附错误反馈）→ 仍败 → `degraded`，树不变，下回合自愈 |
| 非法动作（守卫失败） | 模拟树预检 → 拒绝 → 带反馈重试一次 |
| 用户并发编辑 | parse on demand，天然并入下一回合；planner 落盘前强制 refresh，degraded 即自锁 |
| 进程重启 | 树从 PLAN.md 加载；序号/状态从 private state 恢复；decisions 尾部续推演记忆 |
| 焦点条目划错 | 焦点对 planner 不可见之手：note 提示，等闭合后于父层 surgery |
